# 手冲参数展示卡 —— 实现计划（修订版）

## 功能形态

主页新增「☕ 手冲参数」展示窗口：**单条常驻卡片**，管理员可编辑、全员可见。
内容 = 基本参数 + 图片 + **分段冲煮方案**（无自由文本）：

- 基本参数：方案名、粉量、总水量、粉水比、水温、研磨度
- 分段冲煮：**闷蒸**（时间 + 克重）、**第一段克重、第二段克重、第三段克重**
  （空段不显示；卡片上按 `闷蒸 30s/45g → 一段 120g → 二段 180g → 三段 225g` 流程样式展示）
- 图片：一张，走现有 R2 上传

数据存为**单行配置**（编辑即整体更新），复用现有 JWT admin 校验。

## 实现步骤（沿用现有 diary / images 模式）

### 1. `workers/migrations/0008_brew_card.sql`（新增）

```sql
CREATE TABLE brew_card (
  id           TEXT PRIMARY KEY,          -- 固定 'default'
  bean_name    TEXT NOT NULL DEFAULT '',  -- 方案/豆子名
  dose         TEXT NOT NULL DEFAULT '',  -- 粉量 "15"
  water        TEXT NOT NULL DEFAULT '',  -- 总水量 "225"
  ratio        TEXT NOT NULL DEFAULT '',  -- "1:15"
  temperature  TEXT NOT NULL DEFAULT '',  -- "88-92"
  grind_size   TEXT NOT NULL DEFAULT '',  -- "中细"
  bloom_time   TEXT NOT NULL DEFAULT '',  -- 闷蒸时间 "30s"
  bloom_water  TEXT NOT NULL DEFAULT '',  -- 闷蒸克重 "45"
  stage1_water TEXT NOT NULL DEFAULT '',  -- 第一段克重
  stage2_water TEXT NOT NULL DEFAULT '',  -- 第二段克重
  stage3_water TEXT NOT NULL DEFAULT '',  -- 第三段克重
  image_url    TEXT,
  updated_at   TEXT NOT NULL
);
```

数值统一存 TEXT，单位由 UI 标签显示（允许 "88-92" 这类区间写法）。

### 2. 类型 `src/types/coffee.ts`

`BrewCard`（beanName/dose/water/ratio/temperature/grindSize/bloomTime/
bloomWater/stage1Water/stage2Water/stage3Water/imageUrl?/updatedAt）+
`BrewCardInput`（不含 updatedAt）。

### 3. 后端
- `workers/src/db.ts`：`rowToBrewCard` 映射 + `getBrewCard()` /
  `saveBrewCard()`（`INSERT ... ON CONFLICT(id) DO UPDATE` upsert）。
- `workers/src/index.ts`（仿 diary 块）：
  - `GET /api/brew-card` —— 公开，未设置时返回 `null`；
  - `PUT /api/brew-card` —— 仅 admin；校验方案名非空；`image_url`
    被替换时用现有 `cleanupImage` 删除旧 R2 对象。
- 图片上传复用现有 `POST /api/images`（已 admin-only），不加新接口。

### 4. 服务层三件套
- `src/services/types.ts`：`getBrewCard(): Promise<BrewCard | null>`、
  `saveBrewCard(input: BrewCardInput): Promise<BrewCard>`；
- `httpCoffeeService.ts` / `mockCoffeeService.ts` 各自实现（mock 存 localStorage）。

### 5. 主页展示 `src/pages/HomePage.tsx`
- `useAsync` 增加第 4 个请求 `getBrewCard()`；
- 「统计」与「最高评分」之间插入 `<section className="mt-12">`（☕ 手冲参数）；
- 卡片沿用全站风格：sm 以上左图右文——右侧上半是参数网格（小灰标签+加粗值+单位），
  下半是分段注水流程（闷蒸 → 一段 → 二段 → 三段，箭头/芯片样式，空段隐藏）；
- 空状态：访客不可见该 section；管理员看到虚线占位卡「去设置手冲参数 →」；
- 管理员登录时卡片右上角有「编辑」按钮 → `/brew-card/edit`。

### 6. 编辑表单 `src/pages/BrewCardFormPage.tsx`（新增）
按 `DiaryFormPage` 模板：admin 早退守卫、`useState` 表单对象、`saving` 态、
Toast、保存后 `navigate('/')`。分三个区块：基本参数（6 个短字段）、
分段冲煮（闷蒸时间/克重 + 三段克重，共 5 个短字段）、图片（照抄
`AddCoffeePage` 的隐藏 file input + 预览 + 移除，调 `uploadImage`）。
仅校验方案名非空，其余可选。

### 7. 路由 `src/App.tsx`
`<Route path="brew-card/edit" element={<BrewCardFormPage />} />`（无导航项，
入口在主页卡片）。

### 8. 验证与收尾
- `npm run lint && npm run build`；
- 本地 `db:migrate:local` 后起 `dev:api` + `dev`，浏览器实测：访客视角
  （section 隐藏/展示）、本地注册首个用户（自动 admin）→ 编辑保存 →
  主页显示新卡、空段隐藏、替换图片后旧图清理；
- WORKLOG.md 记录该功能；注明部署顺序：
  `npm run db:migrate:remote` → `npm run deploy:pages`。
